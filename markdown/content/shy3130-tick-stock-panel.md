# tick-stock-panel 深度评测：A 股散户的第一套「自托管量化全流程」
> **一句话总结**：tick-stock-panel（TSP）是一个由个人开发者 shy3130 在 2026 年 6 月开源、仅 3 个月即冲上 5k+ Star 的自托管 A 股量化工作台——把"选股、因子回测、盘中监控、AI 复盘"四件事打包进一个 Docker 容器，填补了"同花顺看盘"和"Qlib 写代码"之间那道尴尬的鸿沟。
**适合谁读**：手里有点 Python 基础、被同花顺公式编辑器束缚过的散户；想跑因子但被 Qlib 劝退的工程化研究者；想给交易系统加一层"AI 复盘自动化"的全栈开发者。

## 一、背景与痛点：它到底在解决什么问题
### 1.1 散户研究 A 股的三重断裂
绝大多数 A 股个人研究者都经历过同样的割裂：
- **看盘软件（同花顺/通达信）**有行情、有指标，但回测能力极其原始，公式语言封闭，因子检验几乎为零；
- **Python 量化框架（Qlib、vnpy、backtrader）**回测能力强，但没有界面，写完策略要在 Jupyter 里看枯燥的净值曲线，更没有盘中实时监控和复盘；
- **云端平台（聚宽、米筐）**用着舒服，但聚宽据传已停服，且策略代码、因子逻辑永远锁在别人服务器上。
还有一个更隐蔽的痛点：**数据源**。AKShare 本质是爬虫封装，东财反爬一升级就大面积失效；Tushare 积分制卡脖子，分钟数据单独 2000 元/年。个人研究者常年处于"有想法没数据"或"有数据没工具"的窘境。
### 1.2 作者的解法：把整条研究流水线塞进一个容器
shy3130 在 V2EX 发帖时提到，项目前身是他自用的两版量化回测系统，重构时索性开源。设计哲学非常清晰——**不是再造一个看盘软件，也不是造一个回测 SDK，而是把"数据接入 → 指标计算 → 选股 → 因子研究 → 回测 → 盘中监控 → 盘后复盘"这七步串联成一个**带 Web 界面的本地闭环**。
> 💡 **一句话比喻**：如果同花顺是"包月健身房的跑步机"，Qlib 是"自己买杠铃组装的地下室"，那 TSP 就是"放在你家里、可自己加配件的跑步机+杠铃二合一"。
### 1.3 一份罕见的克制
README 开头最值得反复咀嚼的是这两句话：
> **明确不做**：不对标同花顺 / 通达信，不内置「AI 荐股 / 涨停预测」。
在一个满地"AI 选股神器"的时代，一个开源项目主动声明自己"不做荐股"是极其罕见的克制。这决定了它从头到尾只输出**工具和流水线**，而**不替你做判断**——这个立场贯穿了整个产品形态（后面在"因子挖掘"那一节还会看到它是怎么落地的）。

## 二、核心亮点与功能剖析
### 模块卡片 1：能力路由矩阵 —— 整个项目最精妙的工程抽象
这是 TSP 最被低估、也最能体现作者工程能力的设计。
> 💡 **通俗解释**：想象你有多家外卖供应商——A 家送米饭、B 家送菜、C 家只送汤。能力路由就是一个智能调度员：根据每家供应商"声称自己能送什么"来决定谁负责哪一道菜。
具体到 TSP：每个数据源插件（TickFlow、fuyao、stock-sdk、YAML 自定义源）需要**显式声明**自己提供哪些数据集（日 K / 除权 / 实时 / 分钟 / 盘口 / 财务 / 龙虎榜），以及这些数据的精度档位。系统用 **fail-closed** 原则做兜底——某个字段没声明单位（`pct_unit`），就直接拒绝接入，绝不静默错误计算。
```
TickFlow SDK  ─┐
fuyao (同花顺)  ─┼─→ 能力路由矩阵 ─→ Parquet / DuckDB 存储
stock-sdk     ─┤   (档位探测、
YAML 自定义源 ─┘    fail-closed)
```
**实际收益**：同一个策略、同一份回测代码，你今天用 TickFlow 免费档跑日 K，明天升级 Pro 档切换分钟数据，策略层完全无感——指标口径、回测逻辑不变。这是"换数据源如换灯泡"的工程体验，在开源量化工具里非常稀缺。
---
### 模块卡片 2：选股引擎 + 68 列指标流水线 —— Polars 的速度红利
**核心数字**：25 个内置策略 + 分钟级策略 + 自定义信号 + AI 生成；MA/EMA/MACD/RSI/KDJ/布林/量比等 **68 列指标**一次扫表落盘 enriched Parquet。
底层用 **Polars**（Rust 实现的 DataFrame 引擎）做计算，**DuckDB** 做 SQL 查询，**Parquet** 分区表做存储——这套组合是当前 Python 数据工程界的"性能三件套"，比传统 pandas 快一个数量级。全 A 股 5000+ 只股票毫秒级扫描，意味着你可以真正做"全市场轮动扫描"而不是"抽样研究"。
**存储巧思**：本地只存 15 列基础数据，68 列指标**读取时现算**+ 进程内快照缓存。这样既不浪费磁盘（每只股票多存 53 列指标一年下来很吓人），又保证了指标升级（比如新增一个算子）后无需重新灌数据。
---
### 模块卡片 3：因子平台 + 因子挖掘 —— 它最值得抄的不是代码，是规矩
这一段是整个项目里**最能看出作者价值观**的地方。
**因子平台**提供四件事：IC/IR 检验、分层收益、Newey-West 检验、自定义 DSL 因子编辑器（25 个算子点选式拼装，不需要写代码）。因子库可以**一键生成排名策略**，策略触发器可以直接引用因子条件——研究层和策略层双向打通。
**因子挖掘**做的是嵌套样本外搜索多因子排名组合，但有一条铁律：
> **候选库显式发布、永不自动上线**。
> 🔥 **金句锚点**：机器可以帮你找因子，但那一下"启用"必须你自己点。
> 这条规矩对抗的是量化圈最危险的病——"我把参数调到回测曲线变漂亮了，然后我信了"。
作为一个评测者，我必须说：**这一条设计价值超过项目里任何 1000 行代码**。它把"自动化的诱惑"和"人工的判断责任"切开了，是这个项目能在"AI 工具滥用"时代独树一帜的根本原因。
---
### 模块卡片 4：回测引擎 —— T+1、费用、滑点一样不少
四种研究视图：
| 视图 | 用途 | 关键能力 |
|---|---|---|
| 因子回测 | 验证某个因子是否有 alpha | IC/IR、分层收益、多空组合 |
| 策略回测 | 验证完整买卖规则 | 净值曲线、回撤、夏普、蒙卡回撤、T+1/费用/滑点/止损 |
| 分钟策略回测 | 逐日回放分钟信号 | 分钟收盘入场、分钟级成交明细 |
| 验证 | 防过拟合 | 参数敏感性 + 滚动样本外 |
财务因子用的是**点时口径（PIT）**——公告之前一律空值、绝不填 0，这从源头上避免了"用未来年报去回测过去"的前视偏差。很多个人项目死在这一步，TSP 把它做成了默认行为。
回测跑在 **spawn worker 子进程**，刷新页面、切页都不丢任务，SSE 流式推送进度——这是给"研究过一回测要等 20 分钟"的人准备的实用功能。
---
### 模块卡片 5：监控中心 + 异动监控 —— 从研究走向实战的桥梁
四类监控规则（策略 / 个股信号 / 价格 / 异动），多条件 AND/OR 组合，触发时支持**语音播报（播个股名称和信号）+ 飞书/企微推送 + 弹窗**，触发记录持久化。
异动监控分三个时段：
- **竞价异动**：同花顺盘前风向标（含当日/次日真实收益对照、追高风险标记）
- **盘中异动**：涨停/炸板/翘板/跌停/新高/新低/放量
- **偏移异动**：交易所官方偏离值口径（主板 3 日 ±20%、创业板/科创板 ±30%、北交所 ±40%）
"偏移异动"用交易所官方口径而不是自创阈值，是少见的"合规意识"。
---
### 模块卡片 6：AI 四维分析 + 盘后复盘 —— LLM 的正确用法
TSP 对 AI 的用法非常克制：**不荐股，只做解读和复盘**。
- **个股分析**：日 K + 9 类关键价位 + AI 四维分析（技术面 / 基本面 / 财务 / 消息面）
- **盘后复盘**：自动注入龙虎榜资金动向、盘前风向标对照，生成 Markdown 复盘报告，可定时执行、推送飞书
- **AI 兼容**：OpenAI 兼容接口，DeepSeek / 通义 / Ollama 都能接
策略还可以让 AI 生成——用大白话描述选股逻辑，AI 写成 Polars 策略代码。这是和 daily_stock_analysis 的本质区别：后者 AI 帮你"下结论"，前者 AI 帮你"写工具"。


### 3.4 一个隐藏的坑：Docker 里的 Codex CLI 前置步骤
2026 年 7 月 14 日之后，Docker 镜像内置了固定版本的 **Codex CLI**，Compose 会把主机的 `~/.codex` 只读挂载进容器——意味着**你得先在主机完成 Codex 登录**。
Windows 用户还要在 `.env` 里显式指定：
```bash
CODEX_HOME_HOST=C:\Users\你的用户名\.codex
```
如果只是想跑"选股+回测+监控"不用 AI，这步可以跳过。但 README 没把这件事放在最显眼的位置，**这是新人最容易卡壳的地方**，评测里必须点名。
### 3.5 真实的代码示例：自定义策略长什么样
来自官方文档与社区示例：
```python
from app.strategy.base import BaseStrategy
import polars as pl
class MACrossVolumeStrategy(BaseStrategy):
    """5 日均线上穿 20 日均线 + 成交量 1.5 倍放大"""
    name = "ma_cross_volume"
    timeframe = "daily"
    def generate_signals(self, df: pl.DataFrame) -> pl.DataFrame:
        df = df.with_columns([
            pl.col("close").rolling(5).mean().alias("ma5"),
            pl.col("close").rolling(20).mean().alias("ma20"),
            pl.col("volume").rolling(5).mean().alias("vol_ma5"),
        ])
        return df.with_columns(
            ((pl.col("ma5") > pl.col("ma20")) &
             (pl.col("volume") > 1.5 * pl.col("vol_ma5")))
            .cast(pl.Int8).alias("signal")
        )
```
**这段代码的信息量**：继承 BaseStrategy，声明 `timeframe` 让能力路由自动分发到日线执行链；Polars 表达式风格，没有 for 循环，全列并行——读懂这一段就能看懂整个策略体系的写法。

## 七、局限与不足：一个诚实的清单
1. **仅覆盖 A 股**，没有港美股、没有加密货币、没有期货期权。如果你的研究视野跨市场，它无法替代 daily_stock_analysis 这类工具。
2. **小白门槛依然真实存在**。README 说"小白请绕路"不是谦虚：要理解"因子"、"IC/IR"、"滚动样本外"、"PIT"这些概念才能用好它。Docker 里 Codex CLI 那个前置登录坑也足够劝退一批人。
3. **实时数据要钱**。TickFlow 免费档只有历史日 K；Starter ¥49/月、Pro ¥99/月、Expert ¥199/月。fuyao（同花顺 REST）也要自备 API Key。换句话说，"零运维"不等于"零成本"，**零的是运维成本，不是数据成本**。
4. **明确禁止商用**。MIT 协议 + "严禁商业用途"的 README 声明形成了一种法律上的灰色地带，你要拿它做商业产品/接客户是有风险的。
5. **无正式 Release**，意味着没有版本号、没有变更日志、没有稳定分支——你永远在用 main 分支，随时可能因为一次 push 改变行为。
6. **回测≠实盘**。这是所有回测框架的通病：T+1/滑点/手续费都模拟了，但流动性冲击、涨跌停无法成交、停牌、复牌跳空等真实世界的脏东西依然会让你的策略在实盘上"水土不服"。README 的免责声明写得很清楚：
   > **回测结果不代表未来收益**。
7. **个人项目的长期风险**。聚宽停服的前车之鉴还热乎，个人项目可能因为作者工作变动、失去兴趣、TickFlow 商业策略调整而停滞。建议把它作为**研究工具**而非**关键基础设施**。
8. **数据源绑定 TickFlow 的隐性倾向**。虽然架构是插件化的，但默认体验、文档示例、作者推荐码都指向 TickFlow——这里有潜在的利益关联，需要保持清醒：**它不是"中立的数据源适配器"，而是"TickFlow 的最佳客户端"**。
