# 把人类第一次登月的"大脑"装进浏览器：GitHub 仓库 chrislgarry/Apollo-11 深度评测
> **一句话总结**：这是一份把"把人类送上月球的那 40,000 行汇编代码"原封不动搬上 GitHub 的电子标本——它不能跑、不能编、不能装进你的项目，但只要你有耐心读完一小段，就能亲眼看见 1969 年的人类是用怎样一种"几 KB 内存 + 手写汇编 + 巨量注释"的方式，把两个宇航员送到月面上又活着接回来的。
Star 数 7 万+、212 位贡献者、GitHub 全球仓库热度排名 Top 300 以内——这个数字放在今天任何前沿项目身上都属常见，但一个**没有构建脚本、没有依赖、不发布 npm 包、甚至两年才动一次**的"考古仓库"能持续攀星，本身就是最硬核的口碑。

## 1. 背景与痛点：一份代码为什么会在 47 年后变成爆款
要理解这个仓库的价值，得先回到 1969 年。
阿波罗飞船上跑着一台叫 **AGC（Apollo Guidance Computer，阿波罗制导计算机）** 的机器，指令舱（CM）和登月舱（LM）各装一台。它由 MIT 仪器实验室（也就是后来的 Draper Lab）开发，时任"Colossus 程序设计负责人"的 **Margaret Hamilton**——软件工程这个职业之所以存在，很大程度上要归功于她和她的团队把"可靠性工程"这套方法论在 AGC 上第一次真正跑通了。
这台机器有多寒酸？以今天的眼光看几乎是玩具级别的配置：
| 项目 | AGC Block II 规格 | 折算成今天的参照 |
|---|---|---|
| 字长 | 15 位数据 + 1 位符号（反码） | 比你手机上任何一个 int16 都还窄 |
| 可擦写内存 RAM | 2048 字 ≈ 4 KB | 一张手机随手拍的 JPEG 的 1/300 |
| 固化程序 ROM | 36,864 字 ≈ 72 KB | 一段 30 秒的微信语音 |
| 制造数量 | 全部 57 台，DSKY 键盘 138 块 | — |
数字来自 Virtual AGC 项目的官方梳理，而这台机器要跑的是**实时导航、姿态控制、着陆算法、中断调度**——即便放到今天也是嵌入式工程师的眼中钉级别的难题。
但这些代码本身其实早就"公开"了——MIT 博物馆保存的硬拷贝早就被扫描，Paul Fjeld 负责图像数字化、Deborah Douglas 协调，Ron Burkey 领衔的 **Virtual AGC 项目**把扫描件逐行转录成了可读、可汇编的文本，挂在自己的 ibiblio.org/apollo 网站上。问题在于：那些源码"躺在一个几十年没换过 UI 的老网站里，搜索引擎基本看不见"。
**痛点出现了：人类最珍贵的一段软件遗产，缺乏一个现代开发者会主动去浏览的地方。**
2016 年 7 月，前 NASA 实习生 **Chris Garry** 把这批转录稿整建制地 fork 到 GitHub，仓库命名 `Apollo-11`，README 里只保留了两件事：忠实标注"这是 Virtual AGC 和 MIT 博物馆数字化成果的镜像"，以及明确欢迎任何发现转录错误的 PR。
一周之内，Gizmodo、TIME、Futurism、Design News 全部跟进报道，前端工程师、设计师、初中生、历史学者——一堆从来没碰过汇编的人涌进去翻代码，然后被里面那句**`BURN, BABY, BURN`**（点火例程的注释开头，借用自当时 Detroit 电台 DJ 的流行口号）逗得截图刷屏，仓库一夜爆红。
从那时到现在，仓库基本保持着"考古标本"的姿态：**代码本身不会动，动的只是源源不断被发现的转录错字、被新加的注释、以及一批批被它带进计算机史坑里的人。**

## 2. 核心亮点与功能剖析：它到底"好"在哪
### 2.1 仓库结构：一张地图看懂两艘飞船的大脑
打开仓库，两个顶层目录，对应阿波罗 11 号任务的两台 AGC：
```
Apollo-11/
├── Comanche055/     ← 指令舱（CM）上的 AGC 程序，代号 Colossus 2A
│                       1969 年 4 月 1 日 10:28 汇编通过
├── Luminary099/     ← 登月舱（LM）上的 AGC 程序，代号 Luminary 1A
│                       1969 年 7 月 14 日 16:27 汇编通过（发射前两天）
├── CONTRIBUTING.md  ← 主要为转录错误修正服务
└── README.md
```
命名很有意思：**指令舱程序叫 "Colossus"（巨人），登月舱程序叫 "Luminary"（发光体）**——NASA 那一代工程师给软件起名的浪漫，比今天的"v2-final-FINAL"高了一个次元。
仓库顶部明确标注"Public domain"（公有领域），来源引用了 NASA 合同 NAS 9-4065，以及那个在今天看来像圣迹一样的签名页：
| 提交人 | 角色 | 日期 |
|---|---|---|
| **Margaret H. Hamilton** | Colossus 程序设计负责人 | 1969-03-28 |
| Daniel J. Lickly | 任务程序开发主任 | 1969-03-28 |
| Fred H. Martin | Colossus 项目经理 | 1969-03-28 |
| Norman E. Sears | 任务开发主任 | 1969-03-28 |
| Richard H. Battin | 任务开发主任 | 1969-03-28 |
| David G. Hoag | 制导与导航项目主任 | — |
| Ralph R. Ragan | 仪器实验室副主任 | — |
> 换句话说，**你在 GitHub 上能直接看到 Margaret Hamilton 本人签字的源码仓库**——这个事实的震撼程度，可能比代码本身还高。
### 2.2 技术栈：一台"冻结在 1966 年"的计算机
AGC 的指令集名叫 **AGC4**，只有十几个基础指令，但因为它把 1960 年代硬件工程师的脑洞塞得满满当当，今天读起来像破解密码。常用的几个助记符：
| 助记符 | 含义 | 类比到 C 语言 |
|---|---|---|
| `TC` | Transfer Control（跳转） | `goto` / `call` |
| `CA` | Clear and Add（清零累加器再载入） | `A = x;` |
| `TS` | Transfer to Storage（写回内存） | `x = A;` |
| `AD` | Add（加法） | `A += x;` |
| `CCS` | Count, Compare and Skip（计数比较跳转） | 循环 + 分支的合体 |
| `BZF` | Branch if Zero to Fixed（零则跳转） | `if (A == 0) goto L;` |
| `EXTEND` | 进入扩展指令集 | 切换指令前缀 |
RAM 里那个 2048 字的"小抽屉柜"还要被实时分割给导航、控制、用户接口三块用——所以代码里你会看到大量**EBANK、FBANK 段切换指令**，本质上是手动管理"换页"。**Margaret Hamilton 团队真正做出的创新，是给这台机器装了一个带优先级调度的 Executive 程序**：当任务过载时，低优先级任务被自动丢弃，高优先级任务保命优先——这就是登月过程中著名的 **1202 程序报警**（Executive Overflow - No Core Sets）背后那套机制，也是登月舱最终没坠毁的直接原因。
### 2.3 代码的真实长相：注释多到像小说
很多人对汇编的刻板印象是"天书、没注释、看不懂"。**AGC 源码恰恰相反——因为 MIT 团队当时就意识到代码是给未来工程师读的，注释密度高到接近散文**。一段典型的 Luminary099 片段长这样（点火例程 `BURN_BABY_BURN` 的开头节选，仅做格式示意）：
```assembly
        BANK 34
        COUNT*  $$/DSPACT
# BURN, BABY, BURN -- MASTER IGNITION ROUTINE
#
# SUBROUTINE CALLS: GOPOST, GOPERF1, R02BOTH, R22DSPL
# THE PURPOSE OF THIS ROUTINE IS TO ZERO THE DESCENT
# RATE COUNTER AT IGNITION FOR ALL P63 AND P64 BURNS
BURN,BABY,BURN  TC      BANKCALL       # 调用 BANKCALL 进入子程序
                CADR    GOPERF1        # GO TO PERF. COUNTERS ROUTINE
                CAF     PRIO26         # 设置优先级 26
                TC      NOVAC          # 调用导航计算
                ...
```
**读起来的感觉，更像在读一本带汇编注脚的工程文档，而不是在读代码。** 这就是为什么这个仓库能让非程序员也看得津津有味——光是把所有注释挑出来读，就相当于读完一本 NASA 工程师的随笔集。
> 💡 **给小白的阅读建议**：先别管指令。打开 Luminary099 目录，把所有 `.agc` 文件的注释部分粗读一遍，你会依次遇到：
> - **`BURN_BABY_BURN.agc`**：点火主例程（朋克命名风格的元凶）
> - **`GUIDANCE_NAVIGATION.agc`**：制导与导航（数学味最浓）
> - **`SERVICE_MODULES.agc`** / **`LUNAR_LANDING_GUIDANCE_EQUATIONS.agc`**：登月段的核心数学
> - 以及各种自称 "TRASHY LITTLE SUBROUTINE"（烂小例程）的自嘲注释——这些是当年工程师们表达工作情绪的出口
### 2.4 深度剖析：一份"不能跑"的代码为什么具有极高的工程价值
如果你只把 Apollo-11 当"猎奇物品"，那就低估它了。下面三层价值值得分别评估：
**① 软件考古学价值**：这是人类第一次完整公开一场太空任务的实时嵌入式系统源码。从今天的视角看，你能学到**在没有调试器、没有单元测试框架、没有 IDE 的条件下，一群人如何用纯粹的人类纪律来对抗 bug**——那套"模块 + 优先级 + 静态分配"的架构，是现代实时操作系统（RTOS）思想的直接祖先。
**② 嵌入式系统教学价值**：如果你在做 STM32、航天软件、汽车电子、工业控制，你会发现 AGC 遇到的每一个问题——内存不够、中断风暴、优先级反转、时钟漂移——**今天你依然会以不同形式遇到**。读它，相当于读完一本"用汇编写的 RTOS 设计模式"。
**③ 文档驱动开发范本**：AGC 源码的注释密度、章节划分、命名规范，即使放在 2026 年也超过大多数商业项目。这段代码能被 50 年后的人读懂，本身就在示范什么叫"可维护性"。

## 3. 上手门槛与运行体验：读完 ≠ 编译
这是这个仓库最容易让新人踩坑的地方，务必看清楚：
> ⚠️ **重要事实**：chrislgarry/Apollo-11 是一个**纯"源码标本"仓库**，它**不附带任何编译工具链**。README 里那句"If you are interested in compiling the original source code, check out Virtual AGC"是唯一线索。
想真正运行这段代码，你需要走另一条路——**Virtual AGC 项目**（作者 Ron Burkey，官网 apollo.josefsipek.net，前身是 ibiblio.org/apollo）。它提供的是完整的模拟环境：
| 组件 | 作用 |
|---|---|
| **yaYUL** | AGC 汇编器：把本仓库的 `.agc` 源码汇编成二进制"绳芯存储"镜像 |
| **yaAGC** | AGC CPU 模拟器：加载二进制后真实执行指令 |
| **yaDSKY** | DSKY（Display & Keyboard）界面仿真：还原宇航员按键那块"数码管+灯"的面板 |
| **yaTelemetry** | 模拟地面遥测终端 |
| **yaACA** | 模拟 LM 姿态手柄 |
所以完整的"玩转路径"是三步：
1. `git clone` chrislgarry/Apollo-11 → 拿到 `.agc` 源码
2. 下载或编译 Virtual AGC 的 yaYUL → 把 Luminary099 汇编成二进制
3. 跑 yaAGC + yaDSKY → 你就能在那个复古的 DSKY 界面上按 `VER 63 ENT`，看着程序号变成 63（Powered Descent Initiation，动力下降点火准备），像 Armstrong 一样开始登月
> ⚠️ **第二个坑**：Virtual AGC 项目在嵌入式平台（比如 Raspberry Pi）上的移植已经多年未更新，社区甚至有人直言"这项目已经停滞了"。在 Linux/macOS 主机上跑通常没问题，但别指望开箱即用。
> ⚠️ **第三个坑**：源码里有些"看起来错"的地方，其实是转录错误（OCR/手抄笔误）。仓库欢迎 PR 修这些错，但**不要**把"我以为是 bug"当成 bug 去提交——那些代码真的把人送上了月球。

## 7. 局限与不足：吹得再天花乱坠也要说清楚
**① 它不能编译、不能集成、没有包管理。** 如果你的诉求是"找一个开源库来加速我的项目"，这个仓库对你毫无价值。请立刻关掉。
**② 阅读门槛依然是真实的。** 15 位反码、`EBANK`/`FBANK` 切换、1.024 MHz 主频、十几个寄存器——这些概念不啃是读不懂的。**看热闹 5 分钟，看懂 5 个月**，这个时间成本要有心理准备。
**③ 仓库本体已经"冻结"。** 除转录纠错外，几乎不会有新东西。如果你想看"活的"阿波罗软件复原项目，请移步 Virtual AGC。
**④ Virtual AGC 工具链的维护也进入低活跃期。** 有用户反映其在 Raspberry Pi 等平台已难以安装。Windows 原生编译也比较折腾，Linux/macOS 最稳。
**⑤ 不要被网上"奇闻轶事"误导。** 诸如 "TRASHY LITTLE SUBROUTINE" 等有趣注释确实存在，但很多自媒体把它们渲染成"NASA 程序员的吐槽文化"——实际上它们更多是特定工程师的个人幽默，不构成整个项目的常态。**本仓库的严肃工程价值远大于它的"梗文化"价值。**
