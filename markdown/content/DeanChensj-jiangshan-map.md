# 江山时序深度评测：把 2,400 年中国史"摊"在一张宣纸舆图上
## 一句话总结
**「江山时序」是一位 Google 资深工程师用 4 个月业余时间、以零框架纯前端写就的 2,400 年中国历史交互地图**——它把谭其骧《中国历史地图集》式的厚重地图册装进了浏览器，让你拖一根时间轴就能看秦扫六合、三国鼎立、宋辽金夏的版图流转，点一座城就能查它跨越 18 朝的建置沿革，搜一个人就能让李白、苏轼、王阳明在地图上"活"起来。
> **核心定位**：数字人文 × 历史地理 × 可视化叙事 × AI Agent 可调用出图——是 GitHub 上少见的"文化重量级"纯前端项目。
---
## 背景与痛点：为什么需要这样一张"地图"？
### 痛点一：读史书时"古今地名对不上"
读《资治通鉴》开篇"三家分晋"（公元前 403 年），你脑中浮现的到底是哪七国？读唐诗遇到"建康""黄州""蓝关""蓟门"，它们究竟对应今天的哪个城市？传统纸质历史地图集（如谭其骧《中国历史地图集》八卷本）信息密度极高但翻检不便，普通读者常常查不到、也懒得查。
### 痛点二：朝代分合"看不清"
战国有七雄并立+周天子+越+巴蜀+中山+义渠；汉末有曹操、袁绍、刘备、孙权、公孙氏辽东等群雄；东晋南北朝还有侨州郡县这种"影子行政区划"。任何静态图都难以呈现"此刻谁占了哪块地、上一刻又是谁"——这正是动态地图才能解答的问题。
### 痛点三：人物行迹"无实感"
李白 24 岁出三峡、游扬州、入长安、与杜甫会洛阳、流放夜郎、终老当涂；苏轼从眉山出发、宦游密州、贬黄州、远放儋州……这些"万里行迹"在教科书里只是一行字，缺一张能"跟着走"的地图。
### 痛点四：AI 时代，大模型"不知道古地名坐标"
让 LLM 画一张"苏轼贬谪路线图"或"霍去病河西之战示意图"，模型要么瞎编经纬度，要么根本画不出来。**历史地理数据需要给 AI 一个开箱即用的"出图引擎"**——这正是江山时序独辟蹊径切入的蓝海。

## 核心亮点与功能剖析
> 原作者 Shangjie Chen 是 Google 的 Staff Software Engineer，从事 AI Agent 基础设施研发，这也是项目"AI 友好"做得如此到位的根本原因。
### 模块 1：拖动时间轴，看王朝兴衰（核心交互）
- **2,400 年 × 18 个历史时期 × 164 张疆域快照**：从战国七雄到中华人民共和国，单画布同时呈现多政权对峙。**朱砂虚线"残影边界"**是它的招牌设计——切换节点时上一阶段的疆界以虚线残影浮现，开疆拓土与失地变迁一目了然。
- **透视镜（X-Ray Lens）**：开启后，现代省界会"叠投"在古地图上，古今对照肉眼可读。
- **同步帝王年号**：拖到唐开元 29 年，地图上同时显示"玄宗李隆基·开元二十九年"——这是其他同类项目都没做到的细节。
- **地理要素同步演化**：黄河改道、云梦泽/罗布泊消长、长城（战国/秦汉/明）、大运河（隋唐/元）、丝绸之路、郑和航线都随年代动态变化。
### 模块 2：点地溯源（Trace Place）——18 朝政区沿革卡
**这是项目最有"文化重量"的功能。** 点击地图上任何古城或名关（函谷关、潼关、剑门关、雁门关、玉门关、阳关、山海关），立刻弹出一张溯源卡：
- **诗词题跋 + 历史小传**：每座城都配有中英双语的"开场诗"。
- **2,400 年建置沿革表**：以战国王侯 → 秦郡 → 汉刺史部 → 唐道 → 宋路 → 元明清行省 → 现代省市的顺序，纵向展示该地的行政归属变迁。
- **定点大事**：标注该地发生过的关键事件（如长安的玄武门之变、临安的风波亭），点击即可一键穿越到那一年。
- **汉阙图标雄关 + 古战场/名胜**：赤壁、垓下、五丈原、兰亭、岳阳楼、滕王阁、蓝关、楼兰、罗布泊、伊塞克湖都在列。
> **示例深链**：`?year=819&place=蓝关&lang=en` 直达韩愈"雪拥蓝关马不前"的现场。
### 模块 3：点人溯事（Person Chronicles）——104 位历史人物万里行迹
内置 **104 位帝王将相、文人高僧**的"生平行迹路线图"——每一步都自动联动底层年代、年号、版图与原典名句：
| 人物 | 行迹亮点 |
|---|---|
| 秦始皇 | 238–221 BCE，从咸阳平嫪毐到王翦灭楚，逐站吞并六国 |
| 张骞 | 138–126 BCE，两度被匈奴扣押仍持汉节，凿空西域 |
| 诸葛亮 | 三顾茅庐→赤壁→入蜀→白帝托孤→南征→北伐→五丈原 |
| 玄奘 | 627–645 CE，单人出玉门关、翻越凌山、抵达那烂陀寺 |
| 李白 | 从碎叶城到蜀中、扬州散金、长安翰林、洛阳会杜甫 |
| 苏轼 | 眉山→开封→密州→黄州→惠州→海南儋州的"文人贬谪史诗" |
| 王阳明 | 余姚→龙场悟道→赣南平匪→35 天擒宁王→绍兴讲学 |
支持 `‹ / ›`、`← / →`、`Space` 自动播放，每切一站，背景地图同步切换到对应年代。
### 模块 4：AI Agent 友好协议（差异化亮点，独此一家）
这是整个项目**最具前瞻性**的部分——它把自身定位为"大模型的历史地理可视化引擎"：
**零坐标双参数 URL 协议**（LLM 不需要猜任何经纬度）：
| 模式 | 示例 URL | 自动渲染 |
|---|---|---|
| 0D 单点 | `?year=819&place=蓝关` | 跳转到唐元和十四年，落针蓝关，弹出沿革卡 |
| 1D 同年多站 | `?year=763&place=剑外,巴峡,巫峡,襄阳,洛阳` | 绘制杜甫"闻官军收河南河北"的归乡路线 |
| 4D 跨年多站 | `?year=1079,1080,1094,1097&place=湖州,黄州,惠州,儋州` | 自动配对年份-地点，绘制苏轼宦游长卷 |
**开箱即用的 Agent Skill**：
```bash
# 一行装进 Claude Code / Gemini / Jetski 全局技能目录
mkdir -p ~/.claude/skills ~/.gemini/config/skills \
  && cp -r skills/jiangshan-atlas ~/.claude/skills/ \
  && cp -r skills/jiangshan-atlas ~/.gemini/config/skills/
```
**CLI 一键出图**（供 LLM Tool Call 使用）：
```bash
python3 skills/jiangshan-atlas/scripts/jiangshan.py \
  --year 819 --place 蓝关 --out /tmp/languan_819.png
python3 skills/jiangshan-atlas/scripts/jiangshan.py \
  --year 1079,1080,1094,1097 \
  --place 湖州,黄州,惠州,儋州 --out /tmp/sushi_exile.png
```
**Playwright / WebMCP JS API**：`window.atlasAPI.locate({year, place})`、`inspect({year, place})`、`resolvePlace(place, year?)` 可在浏览器自动化里直接驱动地图。还附带 `llms.txt` 机读规范——这是 2025–2026 年兴起的 LLM 友好标准，作者跟进得极快。
### 模块 5：彩蛋——舆图寻址挑战
输入 `quiz` 进入"古地名小试"：系统隐去所有地名标签，凭史料线索（"西汉武帝元狩二年"提示河西走廊+长城+山脉水系）让你**盲猜扎针**，按球面距离计分。10 轮通关后授予"太史令·舆图大家""职方郎中"等古代官衔——兼具趣味性与历史地理素养训练。

## 技术栈与架构解析
### "反主流"的零依赖纯前端架构
```bash
# 完全没有 npm install、没有 Webpack、没有 Babel
git clone https://github.com/DeanChensj/jiangshan-map.git
cd jiangshan-map
python3 -m http.server 8000   # 一行启动
```
- **语言构成**（来自 GitHub API）：JavaScript 2.09 MB / CSS 128 KB / HTML 91 KB / Python 26 KB / Dockerfile 69 字节。
- **零 React / Vue / Webpack**：用原生 ES Modules + Canvas/SVG 混合渲染——Canvas 负责大面积疆域填色与动态河流，SVG 负责可交互的城池、关隘、行迹弧线。这是**典型的"性能派"选择**：首屏极快，无构建链，无 node_modules 黑盒。
- **数据驱动而非代码驱动**：18 个朝代、164 张疆域快照、104 位人物、1,000+ 城池与关隘全部以结构化数据（JSON/GeoJSON）存储，前端只是渲染引擎。作者还写了详细的 `CONTRIBUTING.md`，规定数据校验规则，方便社区贡献。
- **~127 MB 仓库体量**：绝大部分是数据文件（矢量边界、地标坐标、人物事件库），代码本体其实不大。
- **作者签名提交**：所有 commit 都经过 GPG 签名验证——这是工业级团队的工程素养。
### 工程化亮点
- **深链可分享**：`?year=...&place=...&lang=en` 全部参数化，便于教学、引用、分享。
- **AI Skill CLI 零依赖 Python 脚本**：用 Playwright 截图，无外部依赖，可以直接塞进任何 Agent 工具箱。
- **Dockerfile 已存在**：虽然只有 69 字节，但说明作者预留了容器化部署路径。

## 局限与不足（客观中立）
1. **疆域边界为"示意近似"**：作者本人明确承认这不是测绘级精度。如果做严肃学术论文的图表引用，仍需要回到 CHGIS 原始数据。
2. **暂未覆盖商/西周/春秋**：当前起点是公元前 403 年（资治通鉴开篇），商朝与春秋是社区高频呼声，Issue 已开出，但数据尚未入库。
3. **单维护者主导**：398/410 commits 来自作者一人，长期可持续性依赖个人精力，存在"作者停更即停滞"的隐忧。
4. **GPL-3.0 协议**：商业闭源集成需谨慎（衍生作品必须同样开源）；这与 MIT 协议的宽松度有显著差距，部分早期版本 README 一度写成 MIT，现已统一为 GPL-3.0。
5. **数据/图片体量大**：仓库 ~127 MB，克隆与首屏加载在国内弱网环境下不算极速。
6. **尚无国际化覆盖**：界面支持中英双语，但仅限中国疆域，不支持世界史并置（Issue #213 已提出）。
7. **移动端体验一般**：作为桌面优先的纯前端作品，小屏拖动时间轴与点击细节操作存在精度问题。
8. **无单元测试/CI 红绿标记**：纯前端+数据驱动的项目缺少自动化测试，数据修复依赖人工核对。

## 结语与终极评判
