# career-ops 深度评测：把 AI 变成你的私人猎头（开源、本地、可脚本）
---
## 一句话总结
career-ops 是一个跑在你本地 AI 编程 CLI 里的“求职指挥中心”：自动扫职位、按 A-H 结构化给出 1–5 分、为每条 JD 生成 ATS 化 PDF 简历、维护申请流水线与故事库——它把 AI 当成你的私人猎头，帮你筛出“值得你花时间”的机会，并由你拍板下一步。
---
## 背景与痛点：为何它会出现？
- 海量信息与时间黑洞：资深与技术岗的 JD 动辄 800 字，每天看到 10 条就已是巨量阅读；还要查公司、调简历、写邮件，这些都碎片化到表格或笔记里，容易漏掉、难复盘。
- 不对称的 AI 护城河：公司用 ATS/简历筛选与 AI 面试官来提高效率，候选人却只能用“手动+直觉”做选择——效率与信息不对等。
- 求职流程难以“复利”：每次申请都从零开始，难以复用故事素材、谈判话术与职位调研结果，经验留不住。
- 决策质量与体量难以兼顾：广撒水容易踩雷或被标记为“垃圾投递”；精挑细选又怕错过潜在好机会。
career-ops 正是在这样的背景下诞生的：它不帮你“自动投递”，而是把 AI 放在“分析、准备、追踪”的位置，把“决策与提交”保留给你，提升整体决策质量与效率。
---
## 核心亮点与功能剖析
### 1) 粘在 AI CLI 里的“技能入口”：多 CLI 适配与统一路由
- 支持 Claude Code、Codex、OpenCode、Qwen、Antigravity、Grok Build 等主流 AI 编程 CLI；通过开放的“技能标准”(.agents/skills/career-ops/SKILL.md) 实现统一路由与别名，一处定义、多处生效。
- 典型触发方式（在 CLI 项目目录里）：
  - /career-ops {粘贴JD}：触发“全流程自动管线”（评估+PDF+追踪记录）。
  - /career-ops scan：扫描预配置的公司门户与 ATS 源。
  - /career-ops pdf / cover / email / tracker / batch / contacto / deep 等：分别拉起对应模式。
- 对 Codex 这种不保证斜杠命令的 CLI，也提供了自然语言与 exec 两种调用方式，兼容性做得比较周全。
### 2) A–H 结构化评估（含合法性检查与 1–5 综合分）
- A–F 区块覆盖角色摘要、CV 匹配、职级策略、薪酬调研、个性化建议与面试准备（STAR+R）。
- G 区块是“岗位合法性评估”，独立于评分之外，用来标记诈骗/鬼祟岗位；H 区块仅在 4.5+ 时才起草，避免过度打扰。
- 最终给出 1.0–5.0 的综合分，建议不要投低于 4.0 的职位——这是一个“过滤器”而不是“刷量工具”。
### 3) ATS 化 PDF 与求职素材库
- 使用 Playwright + HTML/CSS（Space Grotesk + DM Sans）生成每条 JD 定制的简历，支持关键词注入、要点重排、区域化等 ATS 友好处理。
- 自动维护“面试故事库”（STAR+Reflection），跨评估累积 5–10 条通用故事，应对各类行为面试；同时提供谈判话术框架、地域差价议价脚本等。
### 4) 门户扫描与批量处理（含零成本扫描脚本）
- 预置 100+ 公司与常用 ATS（Greenhouse、Ashby、Lever、Wellfound 等）的扫描规则，支持自定义查询；提供“零令牌门户扫描器 scan.mjs”直接爬取 73+ 公司 API，而不消耗 LLM 配额。
- 批量模式支持并行评估 10+ 职位，结合 CLI 的 headless worker（claude -p / opencode run）实现多路并发。
### 5) 跟踪、复盘与“求职运营”
- 单一数据源（Markdown pipeline.md）记录每条评估、状态与归档材料；自动合并、去重、状态归一化与健康检查。
- 提供 Dashboard TUI（终端 UI）浏览/过滤/排序；还提供模式分析（渠道转化率、被拒模式、鬼祟岗位检测等）与统计数据，帮助你优化“求职漏斗”。
### 6) 本地优先与 CLI 不可知：成本低、隐私可控
- 核心管线跑在你本地机器的 AI CLI 上下文中，可把 LLM 接到 OpenRouter 免费模型、Ollama 本地模型或任何 OpenAI 兼容端点，不必锁定在某个付费订阅；提供了 RUNNING_ON_A_BUDGET 与 FREE_TIER 文档详细指导省钱/零成本玩法。
### 7) 合规与法律边界设计
- 明确不替你点击提交或发送消息；只做“评估与草稿”，降低合规风险；要求用户遵守各门户 ToS，避免被视为“刷量/滥用”。
- 许可证采用 MIT，代码可自由商用与分发；但“career-ops”名称与品牌有商标政策，商业产品命名需遵循。

  - 素材复利：故事库与谈判脚本会随着评估越用越好用，下次求职不用从零开始。

## 竞品/同类对比：它处在什么位置？
- 与传统表格/笔记工具相比
  - career-ops 能自动拉取与解析 JD，把静态表格变成动态“流水线”，减少手工整理。
  - 它的结构化评估与素材库是传统工具无法自动做到的。
- 与“一键投递/刷子工具”相比
  - 最大区别是“人类在环”：它不做提交、不做点击，只做分析与草稿，由你决定是否发、何时发。
  - 这样更符合平台 ToS 与职业伦理，也避免了账号风险与黑名单。
- 与 SaaS 求职助手（JobApplier 等）相比
  - 本地优先：数据与模型调用由你掌控，可完全跑在本地或你信任的后端。
  - CLI 不可知：不绑定某个供应商，可换模型、换 CLI；且 MIT 开源，可二次开发与定制。
- 与其他开源“职位聚合/爬虫”相比
  - career-ops 不只是聚合，而是“评估—准备—追踪”的一体化管线；更强调“决策质量”而非“数量”。

## 技术栈与架构解析（开发者视角）
### 1) 技术选型
- 语言与运行时：JavaScript/Node.js（MJS），要求 Node.js 18+，推荐 22.5+。安装方式使用 npx 或全局 npm 包，降低环境摩擦。
- 浏览器自动化：Playwright（安装 chromium）用于 PDF 生成与门户爬取。
- 配置与数据：YAML（profile.yml、portals.yml）、Markdown（cv.md、pipeline.md）、JSON 用于状态与中间结果。
- AI 集成：依托于“AI 编程 CLI”的代理能力（如 Claude Code 的工具调用能力），项目本身通过统一的技能入口与路由器分发请求到各模式（modes/*.md）。
### 2) 架构设计要点（来自 README 与公开资料）
- 技能统一入口：.agents/skills/career-ops/SKILL.md 定义技能的元信息与命令路由；通过符号链接/引用适配 .claude/、.qwen/、.antigravitycli/、.grok/ 等不同 CLI 的技能目录，实现“一处写，到处可用”。
- 模式驱动：核心能力封装在 modes/*.md（如 pipeline、scan、pdf、cover、email、tracker、deep、contacto 等），每个模式通过指令/提示词约定任务边界与输入输出。
- 工具脚本：项目包含大量 .mjs 工具（如 scan.mjs、followup-cadence.mjs、salary-gap.mjs 等），负责与外部服务/数据交互、计算与格式转换。
- 数据管线：职位数据、评估报告、跟踪状态都落地到 Markdown/YAML 文件；通过脚本做合并、去重与校验，保证“单一真相源”。
- 插件系统：可选集成 Gmail、Notion、Apify 等，默认关闭，需用户显式开启，减少侵入性。
### 3) 代码组织与 DX（开发者体验）
- 目录结构清晰：根目录包含 modes/、docs/、config/、templates/、lib/ 等，职责分明；README 提供 Quick Start 与手动配置两条路径，适合不同习惯的开发者。
- 文档齐全：SETUP、RUNNING_ON_A_BUDGET、FAQ、SUPPORTED_CLIS、PLUGINS、AUTOMATION 等，覆盖成本、部署、自动化与扩展问题。
- npm run doctor 可做健康检查，减少“环境谜题”；全局安装与项目级初始化并行支持，灵活度高。
### 4) Demo 与最小可复现示例
- 最低门槛启动（推荐新手）：
  1) npx @santifer/career-ops init
  2) cd career-ops
  3) claude（或你习惯的 AI CLI）——首次启动会交互式引导你填写 CV、目标角色、期望薪资与扫描公司，无需手改配置。
- 手动配置路线（适合有定制需求的用户）：
  ```bash
  git clone https://github.com/santifer/career-ops.git
  cd career-ops && npm install
  npx playwright install chromium  # 生成 PDF 必需
  npm run doctor
  cp config/profile.example.yml config/profile.yml  # 编辑你的信息
  cp templates/portals.example.yml portals.yml      # 定制目标公司
  # 在根目录创建 cv.md 放入你的 Markdown 简历
  claude  # 或 codex / opencode / agy / grok
  # 在 CLI 中粘贴职位 URL 或直接粘贴 JD 文本，触发自动管线
  ```
- 常用命令示例（在 AI CLI 中）：
  - /career-ops scan：运行扫描模式。
  - /career-ops pdf：为最新评估的岗位生成 ATS 化简历。
  - /career-ops cover：生成/补全求职信。
  - /career-ops email：草拟申请邮件（只草稿，不发送）。
  - /career-ops tracker：汇总当前流水线状态。

## 局限与不足（客观视角）
- 依赖 AI 编程 CLI 的成熟度与定价：你的体验会受所选 CLI 的能力限制（如长文上下文、工具调用稳定性）；若 CLI 调整收费策略或能力接口，career-ops 也可能受影响。
- 首次使用“冷启动”效果一般：系统需要通过 CV 与对话逐步理解你，早期评估可能偏通用或不够精准；需要主动喂养背景与偏好。
- 维护成本与提供商变化：门户扫描依赖 ATS/公司页面结构，若网站改版或接口关停，需要更新 providers；Issue 中也提到过某端点关闭导致相应 provider 失效的案例。
- 操作心智成本：需要用户熟悉终端与 AI CLI 的交互模式；对“只点网页”的用户而言存在一定学习曲线。
- 评估≠真理：LLM 可能出现幻觉（如误判技能或经验）；系统只给建议，最终决策与校验仍需你来承担，并且 README 与免责声明也明确“无保证”。

## 合规、安全与隐私
- 不代发、不代提交：career-ops 只做分析与草稿，不触发点击与发送；设计上把“合规边界”留给用户控制，降低滥用风险。
- 数据可本地：默认情况下数据留存在本地，可完全使用本地模型（如通过 Ollama）执行评估，控制隐私暴露面。
- MIT 许可与商标政策：代码可自由商用与修改；但“career-ops”名称与商标有使用政策，商业产品命名需遵守。
- 安全审计：第三方平台的自动化安全审计报告显示无高风险依赖或严重提示注入问题（SkillsLLM 汇总）。
