# LongCat-Video 深度评测：美团的开源"长视频特种兵"，到底值不值得你折腾？
> **TL;DR**：LongCat-Video 是美团 LongCat 团队于 2025 年 10 月开源的 **13.6B 参数**视频生成基础模型，凭借 Diffusion Transformer 架构 + 视频续写原生预训练 + 块稀疏注意力，把"分钟级 720p/30fps 长视频生成"从闭源巨头的专属菜，变成了开源世界的主食。**如果你是想做长视频、数字人、故事短片的开发者或内容团队，这是当前开源赛道里最值得认真啃下的一块硬骨头；但如果你是显存有限的个人玩家，或者追求极致画质的一帧党，请三思而后入坑。**

## 一、它是什么？为什么值得写一篇长文？
一句话概括：**LongCat-Video 是美团交给开源世界的一份"长视频生成答卷"**——单模型统一搞定文生视频（T2V）、图生视频（I2V）、视频续写三大任务，主打能力是把 AI 视频从"几秒小片段"拉到"分钟级连贯叙事"。
它凭什么进入评测清单？三个硬指标：
- **参数规模 13.6B**，稠密架构，是当前开源视频模型里参数/显存比做得最优雅的之一
- **官方声称可稳定生成 5 分钟 720p/30fps 长视频**，且不会出现"越往后越糊、颜色漂移"的老毛病
- **MIT 协议开源权重与代码**，商用无门槛，这在闭源动辄限制条款的当下相当稀缺
它不是跑分最猛的，也不是画质天花板，但它在"长"这一维度上，是开源阵营当前**几乎没有同级对手**的存在。

## 二、背景与痛点：为什么大家都在憋长视频？
要理解 LongCat-Video 的价值，得先看清当前 AI 视频生成的三大痛点：
**痛点 1：长视频会"崩坏"。** 主流模型（包括 Wan、HunyuanVideo、Sora 等）多数按"几秒钟片段"训练，一旦想生成 30 秒以上，画面就开始出现颜色漂移、主体变形、镜头风格漂移，业内俗称"越长越糊"。
**痛点 2：多任务要装多个模型。** 想做文生视频、图生视频、视频续写，传统方案要分别部署三个模型，显存和管理成本翻倍。
**痛点 3：闭源 SOTA 看得见摸不着。** Veo3、Seedance 这些模型跑分漂亮，但 API 付费、内容审核严格、无法本地微调，对研究者和垂直行业玩家极不友好。
LongCat-Video 的解题思路可以拆成三招，下面逐一拆解。

## 三、核心亮点与技术架构剖析
### 亮点 1：单模型统一三大任务，靠"条件帧数量"做任务切换
这是它最值得称道的设计巧思。LongCat-Video 用**"条件帧数量"**来区分任务：
- 文生视频：0 帧条件 → 纯靠文本描述
- 图生视频：1 帧条件图 → 严格保留主体属性
- 视频续写：N 帧前序帧 → 接力式生成
打个比方：**就像一台多功能破壁机，你扔什么料进去它就知道该打豆浆还是打果汁，不用换机器。** 相比"一个任务一个模型"的传统方案，参数效率大幅提升，部署时只需加载一次权重。
更关键的是，**视频续写不是事后微调，而是从预训练阶段就原生学习**——这是它能避免长视频崩坏的根本原因。
### 亮点 2：粗到精的两阶段生成策略
这是它能在"分钟内生成 720p"的关键诀窍：
- **第一阶段**：先生成低分辨率的 480p / 15fps 草稿视频，确定时序结构和内容骨架
- **第二阶段**：通过 LoRA 模块超分到 720p / 30fps
**打个比方：先画铅笔稿，再上色渲染。** 这比一上来就硬啃高清数据要省算力得多，也让长视频的时序规划更稳。
### 亮点 3：块稀疏注意力——长序列的"降维打击"
这是 LongCat-Video 技术报告里最硬核的创新之一。传统 3D 注意力的计算量随视频长度平方增长，分钟级视频直接爆炸。
LongCat 的做法是把 3D 视觉 token 分块，**只计算 top-r 关键块之间的注意力，把计算量压到标准密集注意力的 10% 以下**。可以理解为：开会时不让所有人两两握手，而是只让关键部门之间对齐信息，效率高得多。
社区项目 **CacheDiT** 进一步用 DBCache + TaylorSeer 给它叠了 1.7 倍加速 buff。
### 亮点 4：三重加速叠加——50 步降到 16 步
LongCat-Video 在推理端做了三层优化叠加：
| 优化手段 | 效果 |
|---------|------|
| 二阶段粗到精生成 | 计算成本大幅下降 |
| 块稀疏注意力（BSA） | 计算量降至 10% 以下 |
| CFG + 一致性模型蒸馏 | 采样步数从 50 步 → 16 步 |
综合下来，**官方声称推理速度较传统方法提升 10.1 倍**。
### 亮点 5：多奖励 GRPO 强化学习后训练
LongCat-Video 用了 **multi-reward Group Relative Policy Optimization（GRPO）** 做后训练，在文本对齐、视觉质量、运动合理性等多个维度上同时打分优化，而不是单指标吊打。

## 四、硬核成绩单：跑分到底怎么样？
官方在内部 MOS 基准上给出了一份对比表（5 分制），这是判断它真实水平的关键证据：
### Text-to-Video（文生视频）MOS 评分
| 维度 | Veo3（闭源） | PixVerse-V5（闭源） | Wan 2.2-T2V-A14B（开源 MoE） | **LongCat-Video（开源 Dense）** |
|------|-----|-----|-----|-----|
| 文本对齐 ↑ | 3.99 | 3.81 | 3.70 | **3.76** |
| 视觉质量 ↑ | 3.23 | 3.13 | **3.26** | 3.25 |
| 运动质量 ↑ | **3.86** | 3.81 | 3.78 | 3.74 |
| 综合质量 ↑ | **3.48** | 3.36 | 3.35 | 3.38 |
| 总参数 / 激活参数 | - | - | 28B / 14B | 13.6B / 13.6B |
### Image-to-Video（图生视频）MOS 评分
| 维度 | Seedance 1.0 | Hailuo-02 | Wan 2.2-I2V-A14B | **LongCat-Video** |
|------|-----|-----|-----|-----|
| 图像对齐 ↑ | 4.12 | 4.18 | 4.18 | **4.04** |
| 文本对齐 ↑ | 3.70 | 3.85 | 3.33 | 3.49 |
| 视觉质量 ↑ | 3.22 | 3.18 | 3.23 | **3.27** |
| 运动质量 ↑ | 3.77 | 3.80 | **3.79** | 3.59 |
| 综合质量 ↑ | **3.35** | 3.27 | 3.26 | 3.17 |
**客观点评**：
- 在 **T2V** 上，LongCat-Video 用一半参数追平甚至略超 Wan 2.2 的激活参数性能，整体仅次闭源的 Veo3，**开源 SOTA 含金量比较扎实**。
- 但在 **I2V** 上，LongCat 的综合分 3.17 **实际上落后于 Wan 2.2 的 3.26**，运动质量也明显吃亏（3.59 vs 3.79）。**这意味着如果你主做图生视频，Wan 2.2 仍是更稳的选择**——这一点是官方对比表里"数据不会说谎"的真相，必须摆在台面上讲。

## 五、上手门槛与部署体验
### 5.1 硬件门槛：这是它最大的劝退点
LongCat-Video 的 13.6B 参数在 FP16 下权重大约 **27GB+**，加上文本编码器（UMT5-XXL）、激活值、视频 latent 缓存，**显存需求不容小觑**。
| 配置 | 体验预估 |
|------|---------|
| RTX 4090 24GB | 勉强能跑短片段，长视频需 OOM 风险自负 |
| RTX 5090 32GB | 边缘可玩 |
| A100 80GB / H100 80GB / H20 96GB | 官方推荐配置，流畅推理 |
| 多卡（2×GPU 及以上） | 支持 `--context_parallel_size=2` 切分推理 |
| 笔记本 / 无 N 卡 | **不建议**，可考虑 RunningHub 等云端方案 |
### 5.2 软件环境
- Python 3.10、PyTorch 2.6.0 + CUDA 12.4
- **FlashAttention-2 必装**（可切换到 FlashAttention-3 或 xformers）
- 模型权重需从 Hugging Face 下载（数十 GB 级别）
### 5.3 Demo 代码（关键命令一览）
这是最直观能让你感受"它到底怎么用"的部分，照抄就能跑：
```bash
# 1. 克隆仓库
git clone https://github.com/meituan-longcat/LongCat-Video
cd LongCat-Video
# 2. 创建环境
conda create -n longcat-video python=3.10
conda activate longcat-video
pip install torch==2.6.0+cu124 torchvision==0.21.0+cu124 \
    torchaudio==2.6.0 --index-url https://download.pytorch.org/whl/cu124
pip install ninja psutil packaging
pip install flash_attn==2.7.4.post1
pip install -r requirements.txt
# 3. 下载权重（体积大，准备好磁盘）
pip install "huggingface_hub[cli]"
huggingface-cli download meituan-longcat/LongCat-Video \
    --local-dir ./weights/LongCat-Video
# 4. 文生视频（单卡）
torchrun run_demo_text_to_video.py \
    --checkpoint_dir=./weights/LongCat-Video --enable_compile
# 5. 图生视频（单卡）
torchrun run_demo_image_to_video.py \
    --checkpoint_dir=./weights/LongCat-Video --enable_compile
# 6. 视频续写
torchrun run_demo_video_continuation.py \
    --checkpoint_dir=./weights/LongCat-Video --enable_compile
# 7. 长视频生成（核心卖点）
torchrun run_demo_long_video.py \
    --checkpoint_dir=./weights/LongCat-Video --enable_compile
# 8. 多卡切分推理
torchrun --nproc_per_node=2 run_demo_text_to_video.py \
    --context_parallel_size=2 \
    --checkpoint_dir=./weights/LongCat-Video --enable_compile
# 9. Streamlit 网页 Demo
streamlit run ./run_streamlit.py \
    --server.fileWatcherType none --server.headless=false
```
**DX 点评**：脚本命名清晰、参数简洁，属于"**官方脚本能跑通、API 设计合格**"的水平。但目前**没有 Diffusers 原生集成**，也**没有官方 ComfyUI 节点**——社区已经提了 feature request（issue #10480），想用节点流的用户还需要再等等。
### 5.4 家族兄弟：LongCat-Video-Avatar 系列
同一个仓库还托管了**数字人专用版本**：
- **LongCat-Video-Avatar**（2025 年 12 月）：音频驱动的说话人生成
- **LongCat-Video-Avatar 1.5**（2026 年 5 月）：升级为 Whisper-Large-v3 音频编码器，唇形同步更精准，DMD2 蒸馏将推理压缩到 **8 步**，支持动漫/动物等风格化领域
数字人场景下，Avatar 1.5 在唇同步、身份一致性上的表现已可对标 HeyGen、OmniHuman 等闭源方案，**这是 LongCat 系列目前最被低估的实用武器**。

## 八、局限与不足（客观、毫不避讳）
### ⚠️ 局限 1：I2V 综合分其实输给了 Wan 2.2
官方对比表里写得清清楚楚，LongCat 的 I2V 综合分 3.17 落后于 Wan 2.2 的 3.26，运动质量差距更明显。**它不是全能冠军，而是"长视频单科状元"**。
### ⚠️ 局限 2：显存门槛极高
13.6B 稠密架构 + 720p 长视频推理，**没有 80GB 级别的 A100/H100/H20 基本玩不爽**。RTX 4090 用户建议退回 Wan 2.1 1.3B 或走云端。
### ⚠️ 局限 3：训练代码与数据集未开源
目前**只开源了推理代码和模型权重，微调（fine-tuning）脚本未放出**，社区 issue 里已有用户询问（如 #118），尚无官方回应。想拿它做垂直领域微调的团队，要自己写训练 pipeline。
### ⚠️ 局限 4：ComfyUI / Diffusers 生态还在路上
截至本文撰写时，**没有官方 ComfyUI 节点，没有 Diffusers 原生 Pipeline**。对比 Wan 2.2 那种"开箱即用节点流"的成熟生态，LongCat 的工程易用性还差一截。
### ⚠️ 局限 5：评测数据是官方内部基准
MOS 评分来自**美团自建的内部基准**，非 VBench、WorldModelBench 等公开可复现榜单，**独立性打了点折扣**。社区实测反馈整体偏正面，但"超越商业闭源"的说法需要打个小问号。
### ⚠️ 局限 6：原生分辨率与帧率有限
720p / 30fps 是天花板，没有 4K、没有 60fps、没有音频同步（基础版），想要音画同步要等 Avatar 分支或 MOVA 这类模型。

## 十、结语与行动建议
> **一句话终极评判**：LongCat-Video 是 2025-2026 年开源视频生成领域里"**最会做长视频的那一个**"，它用扎实的工程优化（BSA + 粗到精 + 蒸馏）和独特的续写预训练，把一个被闭源垄断了半年的能力还给了社区。它不是全能王，但它是**当前开源赛道里"分钟级 AI 视频"的唯一答案**。
### 不同人群的行动清单
**如果你是开发者/研究者**：
1. 直接 clone 仓库，用官方脚本在 A100/H100 上跑通 `run_demo_long_video.py`，直观感受 5 分钟长视频
2. 读一遍 arXiv 技术报告（2510.22200），重点理解 BSA 和续写预训练的设计
3. 关注 CacheDiT 项目，给你的部署加 1.7 倍加速
**如果你是内容创作者/小团队**：
1. 优先试 **LongCat-Video-Avatar 1.5** 做数字人内容，性价比最高
2. 没 GPU？上 RunningHub 等云端方案，12GB 显存也能玩自动化工作流
3. 长视频生成需求强、I2V 需求弱，才选它；否则 Wan 2.2 更稳
**如果你是普通玩家**：
- 显存 24GB 以下请直接劝退，去看 Wan 2.1 1.3B 或云端体验版
- 关注 ComfyUI 社区的第三方节点适配，等成熟了再上手
### 最后一个判断
LongCat-Video 的出现标志着一个转折点：**开源阵营不再只追平闭源的"短片段画质"，而是开始抢占闭源做不好的"长视频叙事"高地**。如果美团持续投入微调代码开源、ComfyUI 生态、更高分辨率，它完全有可能成为国产开源视频模型里继 Wan 之后的另一个标杆。**值得长期跟进，值得现在就动手跑一遍 Demo。**
