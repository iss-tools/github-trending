## Details

# 一句话总结
Humanizer 是一个“AI 文本除味剂”技能：它基于 Wikipedia“AI 写作特征清单”的 35 条模式，通过一条可复用的 Markdown 提示脚本，让 Claude 等智能体在保持原意的前提下，把“AI 味”重写成更像人写的东西。Star 约 2.8 万、最近持续高频更新、兼容 Claude Code / Codex CLI / Cursor 等多种智能体，写博客、改稿、润色公告的朋友值得立刻关注。 
---
## 背景与痛点
- LLM 输出普遍存在“AI 味”：堆“关键/重要/景观/见证/展示”、用“它不仅是 X，也是 Y”、各种“尽管面临挑战，仍然持续发展”等套路短语。这些并不错，但一看就像模型写的，削弱个性与可信度。   
- 直接让 LLM“写得更像人一点”，效果很不稳定，有时会强行加主观情绪、捏造细节、或改变原意。  
- 不同写作场景需要不同语调：博客要观点与个性，文档与技术内容要保持中性、平实；笼统地“像人一点”常常不匹配场景。  
Humanizer 的诞生就是为了解决这三点：  
- 以 Wikipedia“Signs of AI writing”为权威来源（维基清理项目从成千上万条提交中归纳的 35 类特征），把这些“套路”量化、可检测、可改写，而不是凭感觉。   
- 把“除味”的指令写成一个可复用、可检查、可迭代的 Agent Skill（以 SKILL.md 形式交付），兼容多种智能体平台，避免每次手工重写提示。   
- 明确“不捏造事实、不改原意”的强约束，并区分“个人写作”与“技术/参考类文本”的风格边界。

## 核心亮点与功能剖析
### 1. 基于 Wikipedia“Signs of AI writing”的 35 条模式
Humanizer 把 WikiProject AI Cleanup 的经验转化为“检测—改写—二次校验”的三步流程：  
- 内容层：虚夸重要性/传承、堆知名媒体证明重要性、浅层 -ing 分析、营销语式（“坐落”“令人惊叹”）、模糊来源、套路化的挑战与展望等。   
- 语言层：高频 AI 词（如 additionally、delve、landscape、testament 等）、回避“is/are”、强排三件套、假“从 X 到 Y”范围、被动语态与缺主语、反复改名/重复起句等。   
- 风格层：滥用 em/en 破折号、过多加粗、标题大写、Emoji、花标点、假“深刻真理”“过渡句”“下段预告”、重复标题等。   
- 聊天机器人残留与填充语：“I hope this helps”、“Great question!”、泛泛无物的正向结尾、过度限定词、废话过渡等。   
这些模式来自真实维基条目中被识别出的 AI 写作信号，有经验依据，比“直觉式除味”更系统、更可落地。 
### 2. 先改后检的两遍式流程（“展示工作”）
- 第一遍：在结构上放手改，重排句段、调整节奏。  
- 第二遍：对照模式清单和原文中的“主张”逐条检查，只改仍然像 AI 的部分，同时确保“不改原意、不捏造”。   
- 对“文件模式”，它会保护代码块、数据、frontmatter、链接目标，只处理正文；对“纯文本模式”，先给出中间草稿与简短点评，再给最终版本，方便人审阅与微调。 
这个“展示工作”的设计降低了黑盒焦虑，尤其适合出版前最后一道审校。
### 3. 语音匹配：给个样本，它就学你的味
- 用户可以提供自己的 2–3 段“范文”。Humanizer 会先分析范文：句长节奏、用词偏好、段首习惯、标点/连词/转折词的使用频率等，再改写目标文本。   
- 若范文用了破折号，就保持同等频率；若习惯用省略号，就学着用；不把“个性特征”当成错误处理。   
这相当于一套“逆向风格迁移”：不是从无到有捏造风格，而是从你的样例中学可观察模式并复现。
### 4. 严格的内容保持原则与场景敏感
- 不捏造事实：只有在用户提供或原文有明确事实时，才保留；缺少的细节宁可问或删去，也不编。   
- 场景分野：  
  - 博客/随笔/观点文：允许加入合理的反应、吐槽、幽默、个人评价。  
  - 参考/技术/法律文本：保持中性平实，不随意插主观语。   
这种设计能直接用在“对事实敏感”的工作流（如产品公告、PR 稿、文档更新）。
### 5. Agent Skill：一个 Markdown，接多智能体
- 项目本质就是一份精心编排的 Markdown 提示（SKILL.md），附带安装说明与示例，能被 Claude Code / Codex CLI / Cursor 等“技能感知”的智能体自动发现与加载。   
- 不依赖特定语言或运行时，不用 pip、npm；只要智能体支持“技能目录/Markdown 提示”就能用。  
- 安装极简：  
```bash
mkdir -p ~/.claude/skills
git clone https://github.com/blader/humanizer.git ~/.claude/skills/humanizer
```
（Claude Code 典型路径，其他工具见各自的技能文档。）

## 目标人群与收益
### 适合谁
- 内容创作者（博客作者、专栏作家、Newsletter 主编）。  
- 产品/运营/公关（需要频繁出公告、更新日志、文案、社交媒体文案）。  
- 开发者与文档维护者（写/readme/Changelog/说明文档）。  
- 用 Claude Code / Cursor / Codex CLI 的重度用户，希望把“写完就润色”变成自动流水线的一部分。
### 收益是什么
- 节省时间：把“给 AI 文本除味”的反复改写压缩成一轮技能调用；免了自己逐条对照模式表。  
- 提升可信度：减少“一看就像 AI 生成”的特征，避免读者因“AI 味”而降低信任。  
- 保持个性与原意：在博客与观点文里，它能按样本“学你的味”，保留节奏与字眼，不把个性抹掉。  
- 降低事实风险：强约束“不捏造”，配合“仅改修辞，不改数据/引用/代码”，尤其适合需要对事实负责的场景。

## 竞品/同类对比
### 和“检测+替换”脚本相比
- Humanizer 不只做“词表替换”，而是语义层面的一遍重写+一遍对照检查；能兼顾上下文与语气。  
- 把改写过程透明化（先给草稿再给最终），而不是“暗箱操作”。 
### 和“手工重写提示”相比
- 把 35 条模式与流程固化在一个可维护的 SKILL.md 中，避免每次重新“发明提示”。  
- 持续更新：从 commit 记录看，2026 年几乎每月迭代，增/修模式、兼容新智能体、优化与修复。 
### 和“通用写作教练”技能/提示相比
- Humanizer 的目标是“移除 AI 写作特征”，而不是从零教你写作；其“除味”方向更专一。  
- 源于维基百科编辑社区的经验，并明确标注“当心误判、保持中性”等指导，比通用建议更有操作手册性质。

## 局限与不足
### 需要智能体支持 Skills 生态
- 如果你的工具不支持“技能目录/自动加载 SKILL.md”，就需要手动把提示内容复制到系统提示或对话中，体验稍打折扣。 
### 质量仍依赖背后 LLM 的理解与执行
- 即使提示写得很清楚，不同模型/版本仍可能理解偏差、出现漏改或误改。Humanizer 把风险尽量压低，但不能保证 100%。 
### 并不是“绕过检测”的工具
- 仓库 Issues 中有用户做过盲测，发现“重写质量明显提升，但并未明显改变 AI 检测器的判定”；这说明 Humanizer 的目标是“读着自然”，而非对抗检测。谨慎用在需要合规/声明的场景。 
### 某些激进规则可能删掉有用信息
- 例如“强排三件套”“过度限定词”等规则在极少数语境下会删掉“层级/同时性/必要性”信息。Issues 中有用户反馈这种“信息损失”的边界情况。   
- 实践建议：对涉及排名、时间线、因果链的段落，可人工审验或调整使用强度。

## 快速上手与 Demo（给开发者的核心示例）
### 安装（以 Claude Code 为例）
```bash
mkdir -p ~/.claude/skills
git clone https://github.com/blader/humanizer.git ~/.claude/skills/humanizer
```
### 基本使用
在 Claude Code 中直接调用技能：
```text
/humanizer
[paste your text here]
```
或自然语言触发：
```text
Please humanize this text: [your text]
```
### 改写文件（仅修改正文、不动代码/链接）
```text
Humanize the prose in docs/launch-post.md
```
### 语音匹配（让它学你的味）
```text
/humanizer
Here's a sample of my writing for voice matching:
[paste 2–3 paragraphs of your own writing]
Now humanize this text:
[paste AI text to humanize]
```

## 结语与行动建议
- 如果你经常要“把 LLM 的初稿变成自己的风格”，Humanizer 是目前最系统、最易复用的技能之一：35 条模式来自维基经验、流程透明、支持语音匹配、多智能体兼容、MIT 协议。   
- 它的价值在于：让“除味”可复制、可审阅、可协作；减少“AI 味”的同时，尽量保持原意与事实。  
- 现在就可以做三件事：  
  1) 把它克隆到你的智能体技能目录，试用几次真实文本。  
  2) 准备几段你自己的“范文”，试语音匹配，感受差异。  
  3) 对重要文档，先用它“除味”再人工过一遍，把模板变成你自己的流水线。
